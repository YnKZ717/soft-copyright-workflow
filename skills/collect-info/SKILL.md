# 软著信息收集技能

按 CMMI3 标准和软件工程范式，深度收集软著申请所需的全部项目信息。

## 触发条件

- 用户说"收集信息"、"开始填写项目信息"
- 用户通过 `/collect-info` 命令触发
- 被 `copyright-workflow` 全流程调用

## 执行流程

### Step 0：读取配置文件

从 `{{user_home}}\.claude\config.md` 加载：
- 公司固定信息（自动填充，不再问用户）
- 路径配置（`{{reference_dirs}}`、`{{template_dir}}`、`{{default_output_dir}}`）

### Step 1：确认文档输出路径（必须）

**这是信息收集的第一步，必须先确认。**

使用 `AskUserQuestion` 让用户明确指定文档输出路径：

```
question: "请指定文档输出路径："
options:
  1. "{{default_output_dir}}\{新项目名称}\"
  2. 跳过（使用默认路径）→ AI 代决策（低风险蓝色标注）
  3. 自定义输入 → 用户自己告诉 agent 具体路径
```

**禁止自动选择或猜测路径。**

确认后，**在该路径下检查并补建目录结构**（见下方「统一目录管理」）。

### Step 2：深度问答

按以下顺序逐项询问（已自动填充的跳过）：

每个问题都使用 `AskUserQuestion` 提供选择题：

#### 基础信息
| 信息项 | 说明 | CMMI3 对应 |
|--------|------|-----------|
| 软件全称 | 格式：Neowow + 功能 + 系统/软件 | 项目范围 |
| 软件简称 | 简短有辨识度 | — |
| 版本号 | 首次申请 V1.0 | 版本控制 |
| 软件完成日期 | 必须晚于公司成立日≥6个月 | 版本记录 |
| 软件发表日期 | 必须晚于完成日期 | 版本记录 |
| 源程序量 | 实际代码行数 | 规模估算 |

#### 功能模块（核心）
| 信息项 | 说明 | CMMI3 对应 |
|--------|------|-----------|
| 功能模块列表 | 3-8个核心模块 | 模块划分 |
| 每个模块的输入 | 参数名/类型/必填/说明 | 接口设计 |
| 每个模块的处理 | 核心业务逻辑/算法 | 模块设计 |
| 每个模块的输出 | 返回数据结构/状态变更 | 接口设计 |
| 模块间依赖关系 | 调用关系、数据流 | 架构设计 |

#### 技术选型

|--------|------|-----------|

| 数据库 | MySQL / PostgreSQL 等 | 数据库设计 |

| 部署方式 | Docker / 直接部署 等 | 部署设计 |
| 开发工具 | IDE、版本控制工具 | 开发环境 |

#### 数据库
| 信息项 | 说明 | CMMI3 对应 |

| 表数量 | 大概几张表 | 规模估算 |

#### 接口

|--------|------|-----------|

| 外部 API 数 | RESTful API | 接口设计 |

#### 安全

### Step 3：兜底 1 — AI 代决策

用户选择"跳过"时：
- AI 按行业范式 + CMMI3 标准**自动设计最合理方案**
- 记录到 `ai_decisions` 列表，标注风险等级：
  - 低风险（蓝色）：通用配置、行业标准做法
  - 中风险（橙色）：有多种合理选择，AI 选了其中一种
  - 高风险（红色）：可能不符合用户实际需求，强烈建议审查

**`ai_decisions` 列表格式：**
```
ai_decisions = [
    {"field": "后端框架", "value": "Spring Boot 3.2", "risk": "low", "reason": "行业标准"},
    ...
]
```

**`ai_decisions` 列表用途：** 传递给后续步骤作为**辅助参考**。后续步骤优先使用列表中的风险等级，但不依赖它——如果列表不存在（如单步调用），后续步骤会自主评估风险并标色。

### Step 4：兜底 2 — 参考材料

所有问答结束后，使用 `AskUserQuestion` 询问：
> "你是否有一个参考材料的路径？我可以从中提取信息补全。"

```
options:
  1. 是，我有参考材料 → 用户提供路径（.md / .docx / .txt）
  2. 跳过 → 全按已有信息 + AI 代决策生成
```

### Step 5：输出信息汇总

生成结构化信息摘要，展示给用户确认：
- 用户提供的信息
- AI 代决策的信息（标注颜色/风险等级）
- 公司固定信息（自动填充）

用户确认后，信息锁定，进入下一步。

## 交互规范

### 每个问题必须使用 AskUserQuestion

```
question: "请选择后端框架："
options:
  1. Spring Boot 3.2（推荐）
  2. FastAPI（Python）
  3. 跳过（AI 代决策）
  4. 自定义输入 → 用户自己告诉 agent
```

## 行为约束

### 必须做到
- ✅ 先确认文档输出路径（第一步）
- ✅ 按统一目录管理规则检查并补建目录（见下方「统一目录管理」）
- ✅ 自动填充公司固定信息，不再问用户
- ✅ 每个问题使用 AskUserQuestion 提供选择题
- ✅ 每个模块必须收集输入/处理/输出
- ✅ AI 代决策必须标注风险等级并记录到 `ai_decisions`
- ✅ `ai_decisions` 作为辅助参考传递给后续步骤（后续步骤会自主判断，不强制依赖此列表）
- ✅ 最终输出信息汇总供用户确认

### 禁止做到
- ❌ 不问用户就直接用 AI 代决策（除非用户明确选"跳过"）
-  扫描或遍历任何文件夹/目录
-  自动选择或猜测文档输出路径
-  信息未确认就进入下一步
- ❌ `ai_decisions` 信息丢失或中断传递
- ❌ 删除用户已有的任何目录或文件（只允许补建缺失目录）

## 统一目录管理

**所有会输出文件的技能都必须遵守此规则。**

统一目录结构：
```
{输出路径}\{软件名称}\
├── result\            ← 软著文档
├── .tmp\              ← 临时脚本
├── printscreens\      ← 使用说明书截图
└── illustrations\     ← 设计说明书插图
```

每个技能在输出文件前，必须检查所需的子目录是否存在：
- **缺失** → 自动创建该子目录
- **已存在** → 直接使用，不做任何修改
- **用户自建的其他目录**（如 `backup/`、`notes/` 等）→ 绝对不碰，不删不改

**核心原则：只增不删。** 技能只能补充缺失的标准目录，绝不能删除、重命名或移动用户已有的任何文件夹或文件。
