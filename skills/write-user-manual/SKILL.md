# 软著使用说明书撰写技能

当用户需要撰写软著使用说明书时触发。

## 触发条件

- 用户说"帮我写XX的使用说明书"、"生成XX系统的说明书"
- 用户通过 `/write-user-manual` 命令触发
- 被 `copyright-workflow` 全流程调用

## 前置判断

**有操作界面 → 使用说明书；无操作界面 → 设计说明书。**

如果用户的项目是纯后端 API 服务，应提示用户使用 `write-design-doc` 而非本 skill。

## 执行流程

### Step 0：确认截图位置（必须）

**使用说明书需要用户提供截图，这一步必须先完成。**

使用 `AskUserQuestion` 让用户明确指定截图文件的存放路径：

```
question: "请提供截图文件的存放路径："
options:
  1. "{{default_output_dir}}\{项目名称}\screenshots\"
  2. 跳过（生成带截图占位的文档，后续手动插入）→ AI 代决策（低风险蓝色标注）
  3. 自定义输入 → 用户自己告诉 agent 具体路径
```

**禁止自动选择或猜测截图路径。**

### Step 1：确认信息

**优先使用 `collect-info` 已收集的信息。** 如果未收集，则询问：

| 信息项 | 说明 |
|--------|------|
| 软件全称 | 含版本号 |
| 系统简介 | 一段话概括定位、架构、场景 |
| 功能模块列表 | 一级模块及其二级功能 |
| 每个功能的字段 | 每个页面有哪些输入/展示字段 |
| 开发完成日期 | 截图时间必须晚于此日期 |

如果用户只提供软件名称，**根据名称智能推测**功能模块，然后让用户确认/修改。

### Step 2：生成 Word 文档

**文档结构：**
```
封面 → 系统简介 → 登录 → [各功能模块] → 系统设置
```

**每个功能页面必须包含四要素：**
1. **操作描述**（标准句式：在导航栏点击"XX"，然后点击左侧的"XX"将显示…）
2. **截图**（从用户指定的路径获取，居中）
3. **截图说明**（`图N XXX页面`，居中，编号连续递增）
4. **字段说明**（逐行：`字段名：字段说明。`）

**格式要求：**
- 截图中的软件名称需与申请全称/简称一致
- 截图时间需晚于开发完成时间
- 截图中不要出现第三方信息
- 说明书功能需与申请表主要功能描述一致
- 不出现目录

### Step 3：CMMI3 审查

生成后**自动调用 `cmmi3-review`** 审查：
- 功能与申请表一致？
- 截图时间晚于开发完成时间？
- 截图说明编号连续递增？
- 字段说明格式正确？

审查不通过 → 自动修正 → 重新审查

### Step 5：保存文件

**保存位置：** `result\` 目录（在 `collect-info` 确认的输出路径下）

**命名格式：** `{软件全称}V{版本号}-使用说明书.docx`

**截图保存在：** 同级 `printscreens\` 目录
## 行为约束

### 必须做到
- ✅ 必须先确认截图位置（Step 0）
- ✅ 所有操作描述使用统一句式
- ✅ 截图编号全文连续递增
- ✅ 截图说明格式：`图N 页面名称`
- ✅ 字段说明格式：`字段名：字段说明。`
- ✅ 生成后自动调用 cmmi3-review

### 禁止做到
- ❌ 出现目录
-  截图中出现第三方信息
- ❌ 功能描述与申请表不一致
- ❌ 自动选择或猜测截图路径
