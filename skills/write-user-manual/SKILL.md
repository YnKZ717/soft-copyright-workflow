# 软著使用说明书撰写技能

当用户需要撰写软著使用说明书时触发。

## 触发条件

- 用户说"帮我写XX的使用说明书"、"生成XX系统的说明书"
- 用户通过 `/write-user-manual` 命令触发
- 被 `copyright-workflow` 全流程调用

## 前置判断

**有操作界面 → 使用说明书；无操作界面 → 设计说明书。**

如果用户的项目是纯后端 API 服务，应提示用户使用 `write-design-doc` 而非本 skill。

## 执行流程

### Step 0：确认输出路径与目录

**优先使用 `collect-info` 已确认的输出路径。** 如果未收集，则使用 AskUserQuestion 让用户指定。

检查 `result\` 和 `printscreens\` 目录是否存在：
- 不存在 → 创建对应目录
- 已存在 → 直接使用
- 用户自建的其他目录 → 不碰

### Step 1：确认截图位置（必须）

**使用说明书需要用户提供截图，这一步必须先完成。**

使用 `AskUserQuestion` 让用户明确指定截图文件的存放路径：

```
question: "请提供截图文件的存放路径："
options:
  1. "{{default_output_dir}}\{项目名称}\screenshots\"
  2. 跳过（生成带截图占位的文档，后续手动插入）→ AI 代决策（低风险蓝色标注）
  3. 自定义输入 → 用户自己告诉 agent 具体路径
```

**禁止自动选择或猜测截图路径。**

### Step 2：确认信息

**优先使用 `collect-info` 已收集的信息。** 如果未收集，则询问：

| 信息项 | 说明 |
|--------|------|
| 软件全称 | 含版本号 |
| 系统简介 | 一段话概括定位、架构、场景 |
| 功能模块列表 | 一级模块及其二级功能 |
| 每个功能的字段 | 每个页面有哪些输入/展示字段 |
| 开发完成日期 | 截图时间必须晚于此日期 |

如果用户只提供软件名称，**根据名称智能推测**功能模块，然后让用户确认/修改。

### Step 3：生成 Word 文档

**文档结构：**
```
封面 → 系统简介 → 登录 → [各功能模块] → 系统设置
```

**每个功能页面必须包含四要素：**
1. **操作描述**（标准句式：在导航栏点击"XX"，然后点击左侧的"XX"将显示…）
2. **截图**（从用户指定的路径获取，居中）
3. **截图说明**（`图N XXX页面`，居中，编号连续递增）
4. **字段说明**（逐行：`字段名：字段说明。`）

**格式要求：**
- **全部使用宋体**，严禁微软雅黑或其他字体
- 一级功能模块标题：宋体 14pt 加粗 左对齐
- 二级功能标题：宋体 12pt 加粗 左对齐
- 操作描述正文：宋体 12pt（小四） 1.5倍行距 两端对齐
- 截图说明（图N）：宋体 12pt 居中
- 字段说明：宋体 12pt 1.5倍行距
- 截图中的软件名称需与申请全称/简称一致
- 截图时间需晚于开发完成时间
- 截图中不要出现第三方信息
- 说明书功能需与申请表主要功能描述一致
- 不出现目录

### Step 4：CMMI3 审查

生成后**自动调用 `cmmi3-review`** 审查：
- 功能与申请表一致？
- 截图时间晚于开发完成时间？
- 截图说明编号连续递增？
- 字段说明格式正确？

审查不通过 → 自动修正 → 重新审查

### Step 4.5：格式自校验

生成后**必须用 python-docx 打开文档自动检查**：

- [ ] **字体唯一性**：全文档只出现「宋体」一种字体，严禁微软雅黑/黑体/仿宋
- [ ] **正文行距**：正文段落行距 = 1.5
- [ ] **正文字号**：正文 run 的 size = 152400（12pt/小四）
- [ ] **截图说明**：居中，字号 = 152400

修正方法：遍历所有 paragraph 的所有 run，强制设置 `font.name = '宋体'` + `font.size = Pt(12)` + `_element.rPr.rFonts.set(qn('w:eastAsia'), '宋体')`。

### Step 5：保存文件

**保存位置：** `result\` 目录（在 `collect-info` 确认的输出路径下）

**命名格式：** `{软件全称}V{版本号}-使用说明书.docx`

**截图保存在：** 同级 `printscreens\` 目录

### 异色字体标注规范（每个生成步骤后必须执行）

**核心原则：AI 自己补全/生成的内容标色，用户明确提供的不标。**

**判断规则：**
1. 用户通过 AskUserQuestion **明确选择了某个选项**的内容 → 黑色（不标色）
2. 用户选择"跳过"，由 **AI 自主决定**的内容 → 按风险等级标色
3. `ai_decisions` 列表存在时，**优先使用列表中的风险等级**；不存在时，AI **自主评估风险**

**风险自评标准：**
- **低风险（蓝色）**：通用操作描述、标准字段说明
- **中风险（橙色）**：有多种合理写法，AI 选了其中一种（如功能模块名称、操作路径描述）
- **高风险（红色）**：可能不符合用户实际界面、强烈建议审查（如具体字段含义、系统简介描述）

**python-docx 实现：**
```python
from docx.shared import RGBColor

def mark_risk(run, risk_level):
    colors = {
        'low':    RGBColor(0x2E, 0x86, 0xC1),  # 蓝色
        'medium': RGBColor(0xE6, 0x95, 0x2A),  # 橙色
        'high':   RGBColor(0xC0, 0x39, 0x2B),  # 红色
    }
    run.font.color.rgb = colors.get(risk_level, RGBColor(0, 0, 0))
```

**执行时机：** 在写入操作描述、字段说明时，对 AI 代决策的段落 run 立即设置颜色。不要等生成完再批量修改。

## 行为约束

### 必须做到
- ✅ 必须先确认截图位置（Step 0）
- ✅ 所有操作描述使用统一句式
- ✅ 截图编号全文连续递增
- ✅ 截图说明格式：`图N 页面名称`
- ✅ 字段说明格式：`字段名：字段说明。`
- ✅ 生成后自动调用 cmmi3-review
- ✅ AI 代决策内容必须按风险等级异色标注（蓝/橙/红），用户明确提供的不标色

### 禁止做到
- ❌ 出现目录
-  截图中出现第三方信息
- ❌ 功能描述与申请表不一致
- ❌ 自动选择或猜测截图路径
