# 软著源代码文档生成技能

当用户需要为软著登记生成源代码文档时触发。

## 触发条件

- 用户说"帮我写源代码文档"、"生成软著代码"
- 用户说"提取源代码"、"整理代码提交"
- 用户通过 `/generate-source-code-doc` 命令触发
- 被 `copyright-workflow` 全流程调用

## 执行流程

### Step 1：确认信息

**优先使用 `collect-info` 已收集的信息。** 如果未收集，则询问：

**使用 AskUserQuestion 提供选择题，每个问题必须包含：预设选项 + 跳过 + 自定义输入。**

| 信息 | 说明 |
|------|------|
| 软件全称 | 与申请表完全一致 |
| 版本号 | 与申请表完全一致 |
| 项目路径 | 源代码所在目录 |
| 编程语言 | 主要语言 |

### Step 2：代码提取

**扫描与过滤：**
```
1. 列出项目所有源代码文件
2. 排除：node_modules/venv/__pycache__/.git、第三方库、自动生成代码、敏感配置
```

**提取优先级（高→低）：**
1. 核心业务逻辑（models, services, controllers）
2. API路由与接口定义
3. 配置文件
4. 工具函数与中间件
5. 前端页面组件（必要时）

**提取规则：**
- 单文件最多取80行，超过时按函数/类边界截断
- 不足30行的文件可整体提取
- 文件之间用 `// ===== 文件名 =====` 分隔
- 保持原始缩进（Python尤其重要）

**禁止包含：**
- 第三方库代码
- 重复代码（同一工具函数只提取一次）
- 纯生成文件（migrations、编译产物、lock文件）
- CREATE TABLE 等 DDL 语句（只允许 DML）

### Step 3：生成 Word 文档

**排版规范：**
| 项目 | 设置 |
|------|------|
| 代码字体 | Consolas |
| 字号 | 10pt |
| 行距 | 固定值14磅 |
| 页边距 | 上2.0cm/下2.0cm/左2.5cm/右2.0cm |
| 页眉 | 软件名称 + 版本号，宋体9pt |
| 页脚 | 页码居中，宋体9pt |
| 段前段后 | 0 |

**页数控制：**
- 目标60页（前30页 + 后30页）
- 每页约50行，总目标约3000行
- 代码不足时扩大文件范围，优先补充业务模块

### Step 4：CMMI3 审查

生成后**自动调用 `cmmi3-review`** 审查：
- 总行数 ≥ 3000 行？
- 前后各30页连续？
- 每页 ≥ 50 行有效代码？
- 页眉信息与申请表一致？
- 代码功能是否与说明书对应？

审查不通过 → 自动修正 → 重新审查

### Step 5：保存文件

**保存位置：** `result\` 目录（在 `collect-info` 确认的输出路径下）

**命名格式：** `{软件全称}V{版本号}-源代码文档.docx`
## 行为约束

### 必须做到
- ✅ 代码功能需与说明书对应匹配
- ✅ 两个软著之间代码不能重复
- ✅ 生成后自动调用 cmmi3-review

### 禁止做到
- ❌ 包含 CREATE TABLE 等 DDL 语句
- ❌ 包含第三方库代码
- ❌ 包含敏感配置（密码、密钥）
