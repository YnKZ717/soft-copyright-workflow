# Word 文档撰写规范

**来源：** 参照 `{{template_dir}}\` 中的所有文档模板 + 用户偏好提炼。

## ⚠️ 核心原则

1. **所有文档、所有元素、所有位置统一使用「宋体」字体**，严禁使用微软雅黑或其他字体
2. **正文统一为宋体小四（12pt）、1.5倍行距、两端对齐**
3. 其余元素（标题、表格等）根据层级自适应字号，但字体永远是宋体
4. 同一文档内不允许出现两种字体

## 字体与字号规范

### EMU 换算
- 1pt = 12700 EMU
- 18pt = 228600 EMU
- 16pt = 203200 EMU
- 14pt = 177800 EMU（四号）
- 12pt = 152400 EMU（小四）← 正文
- 10pt = 127000 EMU（五号）
- 9pt = 114300 EMU

### 各文档类型字体规范

## 行距规范

| 元素 | 行距 |
|------|------|
| **正文** | **1.5倍** |
| 章节标题 | 1.5倍 |
| 表格内文字 | 单倍 |
| 图片说明 | 单倍 |
| 代码 | 固定值14磅 |

## 文档结构模板

### 设计说明书结构（对标 CMMI3 TS 过程域）

```
[封面] 软件全称V版本号 (宋体 36pt 加粗 居中)
[封面] 设计说明书 (宋体 36pt 加粗 居中)
[封面] 上海智灵新境科技有限公司 (宋体 18pt 居中)

第1章 引言
  1.1 编写目的 (宋体 14pt 加粗)
    → 正文 (宋体 12pt 1.5倍 两端对齐)
  1.2 项目背景 (宋体 14pt 加粗)
  1.3 术语与缩略语 (宋体 14pt 加粗)
    → 表格 (宋体 10pt)

第2章 系统详细需求分析
  2.1 功能性需求
    → 模块功能需求表格
  2.2 非功能性需求
    → 正文 + 表格

第3章 全局数据结构说明
  3.1 核心实体关系图 (E-R图)
  3.2 逻辑数据字典

第4章 系统模块详细设计（核心章节）
  4.1 模块划分总览
    → 模块关系逻辑框图
  4.2 模块一·XXX (宋体 14pt 加粗)
    → 功能描述 + 设计图 + 输入 + 处理 + 输出 + 异常处理
  4.3 模块二·XXX
    → 同上...

第5章 接口设计
  5.1 内部接口
  5.2 外部接口（API）

第6章 数据库物理设计
  6.1 表结构清单
  6.2 关键索引说明

第7章 安全与保密设计
  7.1 数据传输安全
  7.2 数据存储安全
  7.3 访问控制

第8章 异常处理设计
  8.1 异常分类
  8.2 处理策略
  8.3 错误码定义
```

**每个模块详细设计必须包含：**
- 功能描述（200-300字）
- 输入条件（参数名/类型/必填/说明）
- 核心业务算法（结构化伪代码）
- 输出结果（数据结构/状态变更）
- 异常与边界处理（参数校验/外部依赖/业务规则冲突）

### 使用说明书结构


## 格式自校验清单

**每个文档生成后，必须逐项检查：**

### 字体检查
- [ ] 全文档只使用「宋体」一种字体（源代码文档代码部分除外，用 Consolas）
- [ ] 不存在「微软雅黑」「黑体」「仿宋」等其他字体

### 字号检查
- [ ] 正文字号统一为 12pt（小四）
- [ ] 章节标题字号层级正确（一级16pt > 二级14pt > 三级12pt）

### 行距检查
- [ ] 正文行距为 1.5 倍
- [ ] 表格内文字行距为单倍

### 段落格式检查
- [ ] 正文两端对齐
- [ ] 标题左对齐
- [ ] 图片说明居中

### python-docx 行距设置方法
```python
from docx.shared import Pt, Emu
from docx.oxml.ns import qn
from docx.enum.text import WD_ALIGN_PARAGRAPH

# 1.5倍行距
paragraph.paragraph_format.line_spacing = 1.5

# 或固定值行距（用于代码）
from docx.shared import Pt
paragraph.paragraph_format.line_spacing = Pt(14)

# 两端对齐
paragraph.alignment = WD_ALIGN_PARAGRAPH.JUSTIFY

# 居中
paragraph.alignment = WD_ALIGN_PARAGRAPH.CENTER
```

## 写作规范
- **不出现目录**
- 每个截图都必须有对应文字描述
- 截图中的软件名称需与申请全称/简称一致
- 截图时间需晚于开发完成时间
- 截图不要出现第三方信息
- 说明书功能需与申请表主要功能描述一致
- 代码功能需与说明书对应匹配
- 操作描述格式：「在导航栏点击"XX"，然后点击左侧的"XX"将显示…」
- 字段说明格式：「字段名：字段说明。」

## 文档保存规则 ⚠️ 重要

**每次修改现有文档时，直接覆盖原文件保存，不要创建_temp或任何新文件名。**

**Why:** 用户明确表示"不要创建新文档了，下一次更改直接覆盖"，创建_temp文件增加了用户的重命名负担。
**How to apply:** 使用 python-docx 修改文档后，直接 `doc.save(原路径)` 覆盖原文件。如果文件被 Word 占用导致保存失败，提示用户关闭 Word 后重试。

## python-docx 代码模板

```python
from docx import Document
from docx.shared import Pt, Emu
from docx.enum.text import WD_ALIGN_PARAGRAPH
from docx.oxml.ns import qn

doc = Document()

# 封面标题
title = doc.add_paragraph()
title.alignment = WD_ALIGN_PARAGRAPH.CENTER
run = title.add_run('软件名称V1.0')
run.font.name = '宋体'
run._element.rPr.rFonts.set(qn('w:eastAsia'), '宋体')
run.font.size = Pt(36)
run.bold = True

# 一级章节标题
heading = doc.add_paragraph()
run = heading.add_run('第1章 引言')
run.font.name = '宋体'
run._element.rPr.rFonts.set(qn('w:eastAsia'), '宋体')
run.font.size = Pt(16)
run.bold = True

# 二级章节标题
sub_heading = doc.add_paragraph()
run = sub_heading.add_run('1.1 编写目的')
run.font.name = '宋体'
run._element.rPr.rFonts.set(qn('w:eastAsia'), '宋体')
run.font.size = Pt(14)
run.bold = True

# 正文（宋体小四 1.5倍行距 两端对齐）
body = doc.add_paragraph()
body.alignment = WD_ALIGN_PARAGRAPH.JUSTIFY
body.paragraph_format.line_spacing = 1.5
run = body.add_run('正文内容...')
run.font.name = '宋体'
run._element.rPr.rFonts.set(qn('w:eastAsia'), '宋体')
run.font.size = Pt(12)
```

## 自动清理

**每次文档生成完成后，必须自动删除生成过程中使用的临时 .py 脚本文件。** 不需要询问用户，直接删除。

## 图片替换

**图表生成后，替换文档中的图片由用户自行完成。** Claude 只负责生成/修改图表 PNG 文件（保存到 `illustrations/` 目录），不负责重新生成文档来替换图片。用户满意图表后自行在 Word 中替换。

**Why:** 用户明确表示"改完不要自己去替换"，用户需要手动调整图片在文档中的位置和大小。
**How to apply:** 生成或修改图表后，告知用户 PNG 文件路径即可，不要主动重新生成 .docx 文档。
