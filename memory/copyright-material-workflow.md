# 软著材料撰写工作流

## 整体流程

```
信息收集(表单) → 信息确认(审核) → 批量生成文档 → 质量检查 → 打包输出
                                    │                  │
                                    ├── 源代码文档      ├── 通过 → 打包
                                    ├── 设计说明书      └── 不通过 → 退回修改
                                    ├── 使用说明书
                                    └── 著作权申请表
```

## 各节点详细设计

### 节点1：信息收集（表单）

用 n8n Form 节点收集以下字段：

| 字段 | 类型 | 必填 | 示例 |
|------|------|------|------|
| 软件全称 | 文本 | ✅ | AIGC质量评估与评分系统V1.0 |
| 软件简称 | 文本 | ✅ | AIGC评分系统 |
| 开发完成日期 | 日期 | ✅ | 2025-12-01 |
| 首次发表日期 | 日期 | ✅ | 2025-12-15 |
| 软件用途描述 | 长文本 | ✅ | 面向AI生成内容的质量检测平台... |
| 主要功能列表 | 长文本 | ✅ | 1.AIGC内容检测 2.质量评分 3.数据报表 |
| 技术特点 | 长文本 | ✅ | 采用B/S架构，基于Python+Vue开发 |
| 运行环境 | 文本 | ✅ | Windows 10+, Python 3.8+ |
| 源代码路径 | 文本 | ✅ | D:\projects\aigc-system\ |

### 节点2：信息确认（人工审核）

展示收集到的信息让用户确认：
- 软件名称是否正确
- 日期逻辑是否合理
- 功能描述是否完整
- 确认无误后继续，有问题则修改

### 节点3：批量生成文档

调用本地 Claude 技能依次生成：
1. `/generate-source-code-doc` → 源代码文档
2. `/write-design-doc` → 设计说明书
3. `/write-user-manual` → 使用说明书
4. `/write-copyright-application` → 著作权申请表

### 节点4：质量检查（自动校验）

| 检查项 | 规则 |
|--------|------|
| 名称一致性 | 所有文档中软件全称必须完全一致 |
| 日期逻辑 | 开发完成日期 ≤ 首次发表日期 ≤ 今天 |
| 功能匹配 | 使用说明书功能需与申请表功能描述对应 |
| 代码匹配 | 源代码功能需与说明书描述对应 |
| 格式规范 | 字体、字号、页边距符合标准 |

### 节点5：打包输出

汇总所有文档路径，输出清单。

## 实施方案

### 方案A（优先尝试）：n8n + 本地 Claude
- n8n 负责：表单收集信息、审核流程、任务追踪
- 本地 Claude 负责：根据 n8n 传来的信息生成文档

### 方案B（备选）：纯本地 Claude 工作流
- 全部由 Claude 充当工作流引擎
- 一键触发全流程
