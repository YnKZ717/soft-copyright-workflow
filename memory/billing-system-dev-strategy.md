# 计费管理系统开发策略

## 核心策略：先搭框架，后填计费

**开发理念：** 将不依赖计费细节的模块先开发完成，计费引擎等调研完成后再填充。

## 可以先搭建的部分（不依赖计费细节）

### 1. 项目骨架
- 前端Vue3项目结构
- 后端Spring Boot项目结构
- 数据库12张表（全部可先建）
- 基础配置文件

### 2. 用户认证模块（完整实现）
- 手机号+验证码登录注册
- JWT Token管理
- 用户信息管理
- 安全审计日志

### 3. 会员订阅模块（完整实现）
- 四级会员定义（PLUS/PRO/MAX/ULTRA）
- 订阅/续费/升降级逻辑
- 到期处理
- 会员价格：PLUS 89/949, PRO 269/2909, MAX 629/6799, ULTRA 1099/11899

### 4. 积分管理模块（框架+四源逻辑）
- 四源积分账户结构
- 积分充值/扣减/退还框架
- 积分流水记录
- Redis分布式锁机制
- 四源：充值积分（永不过期）、每日赠送（当天有效）、团队积分（永久有效）、订阅积分（会员到期后1个月）

### 5. 团队管理模块（完整实现）
- 团队创建
- 成员管理（角色权限）
- 团队积分池
- 积分划拨

### 6. 订单账单模块（框架）
- 订单表结构
- 订单创建/查询
- 支付对接框架

### 7. 数据同步模块（框架）
- 同步接口
- 定时任务框架

### 8. 统计报表模块（框架）
- 数据查询接口
- 报表展示框架

## 需要后填的部分（依赖调研结果）

### 计费引擎核心逻辑
- 具体的计费公式实现
- 各种系数的计算逻辑
- billing-rules.yml配置文件的系数值

### 待调研内容
- 各功能基础价格
- 模型系数
- 清晰度系数
- 时长系数
- 数量折扣
- 质量系数
- 素材费用

## 计费引擎处理方式

### 方式1：Mock数据（快速验证）
```java
public BigDecimal calculateCost(BillingRequest request) {
    // TODO: 待调研完成后实现
    return new BigDecimal("100");
}
```

### 方式2：配置开关（推荐）
```yaml
billing:
  engine:
    enabled: false  # 先关闭，调研完成后开启
    mock-mode: true
```

### 方式3：接口预留
- 定义计费接口
- 创建框架代码
- 不实现具体逻辑

## 开发阶段规划

### 阶段1：搭建框架（1-2周）
- 创建项目骨架
- 数据库建表
- 基础配置
- 预留计费接口

### 阶段2：实现非计费模块（2-3周）
- 用户认证（完整）
- 会员订阅（完整）
- 团队管理（完整）
- 积分管理（框架）
- 订单账单（框架）

### 阶段3：填充计费引擎（调研完成后1-2周）
- 填充配置文件
- 实现计费逻辑
- 完善计费模块
- 前端计费页面

### 阶段4：联调测试（1周）
- 前后端联调
- 单元测试
- 集成测试

## 关键原则

1. **模块化设计** - 各模块独立，可并行开发
2. **配置驱动** - 计费规则从配置文件读取，支持热更新
3. **接口预留** - 计费接口先定义，实现后填充
4. **数据完整** - 数据库表结构一次到位，避免后期改动
